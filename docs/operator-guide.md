# 批量出模板操作说明

给跑批量的人看:把一批空白底商品图做成 Mockup 模板。规则和参数见 [batch.md](batch.md),原理见 [how-it-works.md](how-it-works.md),这里只讲怎么操作。

命令都在仓库根目录执行。

## 一、第一次使用

1. 装 Python 3.12。
2. 在仓库根目录建环境、装依赖:

   ```bash
   python3.12 -m venv .venv
   .venv/bin/pip install -r requirements/base.txt
   ```

3. 向晋卓然要 Replicate 的 token,在仓库根目录新建一个文件 `.env.local`,写一行:

   ```
   REPLICATE_API_TOKEN=r8_xxxxxxxx
   ```

   这个文件不进仓库,不要发给别人。

模型都在 Replicate 上跑,电脑不需要显卡,但要一直联网。源图会上传到 Replicate。

## 二、准备源图

- **只用空白底的图**:商品上不能有印花、文字。带图案的图做出来,换颜色后还看得到原来图案的轮廓。
- 建一个总文件夹,里面每个品类一个子文件夹,**子文件夹名用品类的 slug**,和 vorla mockups 页面的小品类一致,也就是仓库 `presets/` 里的文件名去掉 `.json`,比如 `t-shirt`、`hoodie`、`coffee-bag`、`paper-bag`。
- 图片是 png、jpg 或 webp,放在对应的品类文件夹里;品类文件夹里再分子文件夹也可以。
- 总文件夹下不要直接放图片;以 `_` 开头的文件夹会被跳过,可以用来放别的东西。
- Christmas、Etsy 这类节日、渠道不是品类,模板放在它实际的商品品类下。

```
源图/
  t-shirt/
    001.png
    002.png
  coffee-bag/
    north-coffee.png
```

每张图的 id 由品类文件夹名加文件名得出,比如 `t-shirt/001.png` 是 `t-shirt-001`。抽查页、汇总表、例外清单里都用这个 id。

## 三、先试跑

```bash
.venv/bin/python -I scripts/batch.py 源图 --dry-run
```

只生成配置、不真跑,会列出每个品类认出了几张。文件夹名对不上品类、或者总文件夹下直接放了图,会列出来并停下:改文件夹名;如果是新品类,找晋卓然加。

## 四、正式跑

```bash
.venv/bin/python -I scripts/batch.py 源图 --jobs 8
```

- `--jobs 8` 是同时跑 8 张。一张一张跑时模型会闲下来,每次重新启动要等几分钟,所以要同时跑多张。
- 中途可以 Ctrl+C 停掉,再执行同一条命令会接着跑,已经做完的直接跳过。
- 每张约 1–2 美分;源图长边 2048 时约 1.5–2.5 美分。

结果在 `batches/源图/`(按总文件夹名):

- `report.csv`:每张的结果,`pass` 通过,`fail` 没通过自动校验(后面写了哪一项),`error` 出错(后面写了哪一步),`skip` 按例外清单跳过;
- `review.html`:抽查页,用浏览器打开;
- `logs/<id>.log`:每张的运行记录,出错时看这里。

做好的模板在仓库的 `output/<id>/`,每张一个文件夹,整个文件夹就是一个模板。

## 五、抽查

打开 `batches/源图/review.html`:

- 总览列出每个品类出错、没通过、通过各几张,点品类名进品类页;
- 品类页里出错、没通过的全列出来,通过的先列 48 张做抽样,下面的按钮展开其余的;
- 每张两幅小图。左边分割:绿色是商品(可以换颜色的范围),蓝色是不能印的部位(如袖子、领口),红色是挡在商品前面的东西(如头发、手)。右边:黄线圈出可印区域,红框是默认 Logo 位置。点小图看大图。

看哪些要挑出来:

- 商品少了一块,或者把背景、旁边的东西也算进去了;
- 该扣掉的部位没扣掉(袖子、领口、帽檐、提手等被算进了可印区);
- 头发、手挡在商品上,没有标成红色;
- 商品被裁掉了一部分。

看到有问题的,点卡片右上角「有问题」,选问题类型,可以写一句备注。标记存在这台电脑的浏览器里,关掉页面再打开还在。看完点页面底部「导出例外清单」,会下载一个 CSV。

## 六、把有问题的发给晋卓然

```bash
.venv/bin/python -I scripts/batch.py 源图 --pack 下载的例外清单.csv
```

会在 `batches/源图/` 下生成一个 `...-issues-日期.zip`,里面是这几张的原图、分割结果和你的标记。把这个 zip 发给晋卓然。

## 七、拿回改好的清单后重跑

1. 在仓库外或 `源图` 旁边建一个文件夹,比如 `例外清单/`,把收到的 CSV 放进去。以后收到的每一份都放这里,**不要删旧的**。
2. 重跑时带上这个文件夹:

   ```bash
   .venv/bin/python -I scripts/batch.py 源图 --jobs 8 --overrides 例外清单
   ```

   只有清单里那几张会重做,其他的跳过。清单里标了跳过的不会再做,`report.csv` 里记为 `skip`。

每次运行都要带上 `--overrides 例外清单`。漏带了,改过的那几张会按默认设置重做一遍。

## 八、常见情况

| 情况 | 怎么办 |
| --- | --- |
| 试跑提示文件夹对不上品类 | 改文件夹名;新品类找晋卓然 |
| `report.csv` 里有 `error` | 看 `logs/<id>.log` 最后几行;网络问题直接重跑同一条命令;其他的打包发给晋卓然 |
| 很多张都是同一种问题 | 不用一张张标,告诉晋卓然是哪个品类、什么问题,改品类的默认设置后整类重跑 |
| 想加图 | 放进对应品类文件夹,重跑同一条命令,只做新加的 |
| 换了一台电脑 | 照「第一次使用」装好,把 `源图`、`例外清单` 拷过去;模型的中间结果在 `work/` 下,不拷就全部重做 |
